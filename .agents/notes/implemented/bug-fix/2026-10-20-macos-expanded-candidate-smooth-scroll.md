# Agent Note: macOS 展开候选网格保留触控板像素滚动

Status: implemented

## Problem

#8852：macOS 展开候选网格把触控板的连续滚动距离折算成整行，候选卡片在上下滚动时跳动，无法跟随原生输入法的像素级滚动手感。现有实现仍需只绘制可见行，不能因为平滑滚动把全部候选按钮一次性建出来。

## Decision

[虚拟化原生滚动视图](./2026-10-23-macos-expanded-native-scroll.md)替代本篇的自定义距离累计与逐事件按钮重建；方向、像素位置保持、短末页高度、裁剪和选词契约仍有效。本篇保留先前修复的理由，不将旧决定改写成新方案。

展开网格接收候选面板传来的原始 `scrollingDeltaY`，在宿主保存当前虚拟窗口首行与首行内的像素偏移。滚轮事件只移动视口，跨过完整行时推进虚拟窗口首行；重画时额外绘制被偏移露出的下一行并由内容视图裁切。非精确鼠标滚轮仍按整行移动，键盘方向键和翻页键仍按整行移动并清除像素偏移，普通候选窗继续使用原有的整页滚轮分页。

AppKit 的候选容器使用非翻转坐标：浏览后续候选时累计正偏移，按钮的 Y 坐标加上该偏移；推进虚拟首行和行内偏移抵消，跨行前后同一候选的位移只等于输入的滚动距离。事件方向交给系统，不能额外按自然滚动设置翻转。

像素滚动独立持有视口，不因偏移归零、手势结束、惯性结束或普通重绘而定位回旧高亮。键盘导航、普通滚轮和候选代次重载才交回高亮定位。滚动期间固定开始时的视口高度，包括从短末页展开的情况；首尾只夹住实际越界距离，变行高按测得的行几何归一化。

候选按钮放进独立的 `candidate-expanded-viewport`，其边界同时裁剪绘制和鼠标命中，首行控件、卷轴和卡片留白不参加滚动。主题、读屏、动效和当前按钮身份校验同时遍历该视口，过期视口里的按钮仍不能选词。保留原有可见行虚拟化，不建完整列表视图。

## Alternatives considered

- **继续把触控板距离折算成整行**：最强的理由是改动最小且保持现有测试契约。不选它：这正是 issue 报告的跳动来源，无法提供 macOS 原生输入法的连续滚动。
- **改用 `NSScrollView` 承载完整候选列表**：最强的理由是 AppKit 自带像素滚动和裁切。当时不选一次性建立完整列表的方案：候选按钮、皮肤、焦点高亮和代次重载都已经由输入控制器管理，完整建树会失去现有的大列表虚拟化边界。这个限制来自一次性建树，不是 `NSScrollView` 本身；后续原生方案继续自行虚拟化可见按钮。
- **滚动时重建全部候选按钮**：最强的理由是实现简单，偏移只交给坐标布局。不选它：`all_candidates` 可以很大，完整建树会放大触控板每帧重画的开销，也违背展开网格现有的可见行虚拟化。

## Verification

- 精确触控板事件的连续 delta 在行内移动候选视口，不立即跳整行。
- 跨行后仍只保留可见窗口及必要的相邻行，首尾边界不越界。
- 键盘上下、PageUp/PageDown 和普通候选分页行为保持原契约。
- `shortcut-test --expanded-scroll` 通过合成像素级 `NSEvent` 覆盖方向、双向跨行位移连续性、惯性事件、零位移结束事件、首尾边界、重绘位置保持、短末页高度、独立视口命中裁剪、键盘清零和过期按钮拒选。
- 原有测试直接注入私有偏移并把非翻转坐标中的错误方向写成预期，不能证明触摸板正确；回归必须比较跨行前后同一候选的实际位移。
- 安装、签名和 UUID 核对不等于实体触摸板验收，最终手感由维护者在编辑器中测试。

## Consequences

触控板滚动时卡片随像素距离连续移动，只绘制像素视口覆盖的行；行高会因折行和释义变化而不同，偏移归一化依据实际行几何。独立视口增加一层控件容器，主题、读屏和点击校验需要感知这一层，但不用复制普通候选的绘制逻辑。普通鼠标滚轮和键盘导航保留按行语义，普通候选窗的分页契约不变。
